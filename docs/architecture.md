# 工程设计

## 目标

为本地 Agent 提供单数据库、可配置读写权限的 SQLite MCP 服务。服务采用标准输入输出通信，可以由客户端通过 `npx` 按需拉起，也可以使用 `node dist/cli.js` 或公共接口嵌入现有程序。

## 分层

| 模块 | 职责 |
| --- | --- |
| `cli.ts` | 参数入口、服务生命周期、日志、信号与标准输入关闭处理 |
| `config.ts` | 启动配置校验、默认只读、显式创建策略 |
| `server.ts` | MCP 工具、中文说明、参数结构、工具权限提示、统一结果 |
| `schemas.ts` | 可序列化数据类型、条件表达式、请求限制 |
| `database.ts` | 连接管理、查询游标、元数据、写入事务及回滚 |
| `sql.ts` | 标识符转义、单语句检查、参数完整性和语句类型检查 |
| `errors.ts` | 业务错误代码及原生错误信息 |
| `index.ts` | 可复用的服务和数据库公开接口 |

此设计将协议层与数据库访问层分开，后续可以增加其他传输入口，复用当前工具和数据访问代码。

## 数据库与权限

每个进程只绑定一个普通数据库文件。默认打开只读连接；启用写入后增加独立写入连接，查询仍在只读连接执行。查询连接同时使用 SQLite 文件只读模式和 `PRAGMA query_only=ON`。

工具权限通过启动参数确定：只读时仅注册读取工具，读写时增加写入工具。工具声明的 `readOnlyHint`、`destructiveHint` 供客户端展示和决策使用，实际写入仍由数据库访问层校验。

SQL 文本先执行轻量词法检查，识别字符串、转义标识符、注释、语句边界和占位符。它不承担完整 SQL 解析职责，SQLite 负责最终语法与约束检查。原始查询可以使用 `WITH`；其中尝试执行写入时，由只读连接拒绝。

## 写入一致性

每次结构化写入和原始 SQL 写入均使用 `BEGIN IMMEDIATE` / `COMMIT`。任何异常触发回滚，事务内的影响行数或结果大小超限同样回滚。

事务工具先检查所有语句类型，再开始事务，顺序执行每条语句，并累计直接影响行数。成功时返回每条语句的结果；失败时返回统一错误。

SQLite 的直接影响行数不包含触发器与外键级联造成的变化。DDL 返回 `changes: 0`，避免 SQLite 保留上一条 DML 计数而误报。创建或删除表不能通过直接影响行数衡量。

## 查询与结果

采用迭代游标逐行取数据，达到返回行数或字节预算时结束并释放游标。返回截断状态，客户端需要进一步分页或缩小字段范围。

不安全整数读取为十进制字符串；二进制读取为 Base64 对象。输入支持显式 64 位整数对象、Base64 对象、普通 JSON 标量与布尔值。所有用户值均绑定到预编译语句。

响应同时提供文本与结构化结果，适配不同 Agent 的工具消费方式。字节上限针对结果 JSON；MCP 包装及同时提供的文本副本会增加实际协议消息大小。

## 工程交付

生产包包含编译产物、README、文档、示例、许可证及 npm 自动包含的包元数据。可执行文件保留 Node.js 入口标记，源码映射内嵌对应源代码，方便定位问题。独立源码和测试保留在仓库，运行时依赖仅包含 MCP 服务 SDK 和参数校验库。

测试分为配置与 SQL 检查、数据库行为、真实 MCP 子进程以及 `npx` 安装包验证。持续集成覆盖 Windows 和 Linux，并验证最低支持版本与 Node.js 24。

## 当前边界

当前没有数据库连接池、远程 HTTP、用户鉴权、多数据库动态切换、查询执行时间中断和数据库迁移框架。单个服务进程适用于本地受信任 Agent 的文件数据库操作；若需要多个数据库，可以配置多个 MCP 服务实例。
